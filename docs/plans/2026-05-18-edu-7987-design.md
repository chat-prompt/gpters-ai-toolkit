# EDU-7987 — AI Toolkit 스킬 수정 권한 및 버전 관리 강화

- **Linear**: [EDU-7987](https://linear.app/geniefy/issue/EDU-7987/ai-toolkit-스킬-수정-권한-및-버전-관리-강화)
- **Date**: 2026-05-18
- **Owner**: 현진우 (primadonna@gpters.org)
- **Status**: Design — pending implementation

## Background

김태현님이 ai toolkit의 스킬을 개선하려다 author가 아니어서 거부됨. 진우님 Slack 답변:

1. 작성자 외 수정 가능하도록 열기 (suggest 기능 자주 안 쓰임)
2. 버전 컨트롤·코멘트 강화 (이미 있으나 빼먹는 경우 잦음)
3. 변경 시 toolkit 알림에 코멘트 연동
4. 사용 데이터 정리 (별도 작업으로 분리)

본 설계는 (1)(2)(3)을 한 PR로 묶고, suggest 기능을 완전 폐기한다. (4)는 별도 작업.

## Decisions

### Section 3 — changelog 강제

**서버**
- `packages/lib/src/versioning/skill-version.ts:createVersionOnUpdate`
  - 시그니처: `options: { changelog: string; createdBy?: string }` (changelog required)
  - `changelog: options.changelog || analysis.summary` → `changelog: options.changelog`
  - `analyzeChanges`는 versionType 판정용으로 유지, summary 자동 fallback만 제거
- `packages/lib/src/mcp/handlers.ts:deploySkill`
  - 신규(`!isUpdate`): `explicitChangelog`가 없으면 서버에서 `'Initial release'` 자동 주입 후 진행
  - 업데이트(`isUpdate`): `!explicitChangelog || explicitChangelog.trim().length === 0` 이면 즉시 에러 반환 (`"업데이트 시 changelog는 필수입니다. 이번 변경 사유를 한 줄 이상 적어주세요."`)
- `apps/web/app/api/catalog/[id]/route.ts:PUT`
  - "콘텐츠 변경 감지" = `analyzeChanges(previousContent, newContent).hasChanges === true` (skill-version.ts에서 export)
  - hasChanges가 true면 changelog 빈 값/공백/누락 시 400 응답. hasChanges false면 changelog 면제 (메타데이터만 수정한 경우 버전 생성 자체가 일어나지 않음)

**클라이언트**
- `apps/aitk-cli/src/commands/deploy.ts`
  - `DeployOptions`에 `changelog?: string` 추가
  - `params.changelog = opts.changelog` 전달 (옵션, 서버가 강제)
- `apps/aitk-cli/bin/aitk.ts` deploy 도움말: `--changelog <text>` 옵션 명시, "update 시 필수" 안내
- `apps/web/app/[locale]/admin/catalog/[id]/edit/page.tsx`
  - "콘텐츠 변경 감지" (클라이언트) = content textarea의 dirty 상태(`initialContent !== currentContent`)
  - dirty이면 changelog textarea required + 빈 값일 때 submit 버튼 disable + 안내 메시지
  - 신규 생성 페이지(`new/page.tsx` 등)는 면제 — `'Initial release'` placeholder 표시

### Section 4 — UI 검증 (변경 없음, QA 항목)
- 신규 컴포넌트 추가 없음
- 기존 `VersionPopover`(ItemHero), `ChangelogDisplay`(skill/agent/command/guide/package detail), `UpdateNotificationBell`(Header) 그대로 활용
- `ChangelogDisplay`의 `"No changelog available"` 분기는 과거 데이터 호환 위해 유지

## Data Flow

```
[User edits skill in Claude Code/aitk/Admin UI]
        ↓
[deploy_skill / PUT /api/catalog/[id]]
        ↓
[handlers.deploySkill or PUT handler]
   ├─ 인증 체크 (변경 없음)
   ├─ author 체크: 제거 (Section 1)
   ├─ changelog 검증: 신규=auto-fill, 업데이트=필수 (Section 3)
   └─ catalogItems UPDATE + createVersionOnUpdate
                                   ↓
                       [item_versions INSERT — changelog NOT NULL guaranteed by upstream]
                                   ↓
                       [check_updates API picks up new version]
                                   ↓
                       [UpdateNotificationBell renders changelog.split('\n')[0]]
```

## Error Handling

| 시나리오 | 응답 |
|---------|------|
| 업데이트 시 changelog 비어있음 | MCP/REST 모두 success:false + 한글 안내 메시지 |
| 신규 배포 시 changelog 미지정 | 서버가 `'Initial release'` 자동 주입 → 정상 |
| author 외 수정 (이전엔 거부) | 정상 처리, item_versions.createdBy에 실제 수정자 기록 |
| Suggest 명령/도구 호출 (구 클라이언트) | 서버: 404. 구버전 CLI 사용자에게 `aitk upgrade` 안내는 별도 안 함 (CLI도 v0.5.0으로 업그레이드되면 명령 자체 사라짐) |
