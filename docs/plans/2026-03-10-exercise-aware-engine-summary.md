# 실습 생성 시 최신 도구 자동 반영 — 기획 요약

> 작성: 2026-03-10 · 상태: **v2 (리뷰 반영)** · 배경: Slack 대화 (현진우, 김태현, 윤누리)
> 기술 상세: [전체 아키텍처 문서](./2026-03-10-exercise-aware-engine.md)

## 1. 문제

**Rona가 만드는 실습에 최신 도구(스킬, MCP 서버, CLI)가 반영되지 않는다.**

| 현재 | 이상적 |
|------|--------|
| "Stripe 결제 연동 실습 만들어줘" | "Stripe 결제 연동 실습 만들어줘" |
| → AI가 기억에 의존하여 실습 생성 | → Rona가 실습 구조를 생성 |
| → 구버전 API, 없어진 메서드 사용 | → 복리엔진에서 관련 스킬/MCP 자동 탐색 |
| → 실습이 실제로 돌아가지 않음 | → 최신 도구가 반영된 실습 완성 |

---

## 2. 두 시스템 현황

### Rona — 이미 되는 것

- 도구 문서 37개 자동 싱크 (GitHub → DB)
- AI 모델명 매일 갱신 + 구버전 자동 차단
- 6개 플랫폼별 도구명 자동 변환
- 실습 생성 시 도구 문서 최대 5개 자동 삽입

### Rona — 안 되는 것 (복리엔진 협업 필요)

| 영역 | 현상 | 영향 |
|------|------|------|
| 스킬 큐레이션 | "어떤 스킬이 있고 언제 쓰면 좋은지" 가이드 없음 | 학생이 스킬 존재 자체를 모름 |
| MCP 서버 카탈로그 | 목록/설치법/활용 시나리오 없음 | 기본 도구에만 의존 |
| CLI 도구 | 패키지 목록/설치법/사용 패턴 없음 | 구버전 명령어 사용 |

### 복리엔진 — 현재 지표

| 지표 | 현재 | 목표 |
|------|------|------|
| 스킬 추천 적중률 | 15.5% | 30% |
| 검색 무결과율 | 25.0% | 10% 이하 |
| 카탈로그 규모 | 276개 스킬, MCP 9개 | MCP 15개+ (메타 완비) |

## 3. 핵심 미싱 피스

실습 생성 3단계 중 **2번째가 빠져있다**:

1. 실습 내용을 구성하고 → ✅ Rona 자체 해결
2. **관련 스킬/MCP를 복리엔진에서 찾아오고** → ❌ 연결 안 됨
3. 최신 도구가 반영된 실습이 만들어지는 것 → ❌ 정보 없이 생성

---

## 4. 구현 일정

> 범용 스킬 ~40개가 거의 모든 실습에 매칭 가능하므로, 별도 가치 검증 없이 바로 구현에 진입한다.

### Phase 1a (1주) — 스킬 검색 연동

| 작업 | 담당 | 기간 |
|------|------|------|
| 스킬 검색 API 만들기 | 복리엔진 | 1.5일 |
| 인증 + 접근 제한 + 로깅 | 복리엔진 | 1일 |
| Rona에서 복리엔진 호출하는 클라이언트 | Rona | 0.5일 |
| 검색 결과를 실습에 녹이는 로직 | Rona | 1일 |
| 통합 테스트 | Rona | 1.5일 |

### Phase 1b (1.5주) — MCP/CLI 데이터 보강 + 확장

| 작업 | 담당 | 기간 |
|------|------|------|
| MCP 서버 15개 데이터 보강 (설치법, 시나리오) | 복리엔진 | 2일 |
| CLI 도구 25개 초기 등록 | 복리엔진 | 1일 |
| 카테고리별 스킬 목록 API | 복리엔진 | 1일 |
| 실습에서 스킬 사용 추적 | 복리엔진 | 0.5일 |
| 다양한 주제 + 레벨별 E2E 검증 | 양쪽 | 1일 |

### Phase 2/3 — 보류 (별도 의사결정)

| Phase | 내용 | 전제 조건 |
|-------|------|----------|
| 2 | AI 모델 정보를 복리엔진으로 이관 | Phase 1 안정 운영 2개월+ |
| 3 | 도구 문서 싱크를 복리엔진으로 이관 | 가용성 99.5%+ 실적 3개월 |

이관 시 반드시 **2주간 병렬 운영** 후 전환.

## 5. 역할 분담

> **데이터를 가진 쪽이 API를 제공한다.** 복리엔진은 재료(스킬/MCP/CLI)를 주고, Rona가 요리(실습)한다.

| 원칙 | 설명 |
|------|------|
| 복리엔진은 실습 구조를 모른다 | 실습 스키마, 단계 구성 등을 알 필요 없음 |
| Rona는 스킬을 저장하지 않는다 | 스킬 카탈로그는 복리엔진이 유일한 원본 |
| API는 범용적이다 | "주제 + 기술스택 + 레벨"로 검색 — 실습 전용이 아님 |
| 실습 조립은 Rona의 책임 | 어떤 스킬을 어디에 배치할지는 Rona가 판단 |
| 복리엔진이 죽어도 실습은 만들어진다 | 스킬 정보 없이 기존처럼 생성 (graceful degradation) |

### 학습자에게 보이는 방식

| 원칙 | 설명 |
|------|------|
| 레벨 기반 필터링 | 초보자 → 범용 스킬만, 중급+ → MCP/CLI 포함 |
| 인라인 추천 | 사전 준비에 몰아넣지 않고, 해당 단계 안에서 자연스럽게 노출 |
| 최대 노출 수 | 실습당 스킬 2개 + MCP 1개 (과부하 방지) |
| MCP 대안 제시 | MCP 없이도 진행 가능한 방법 함께 표시 |
| 구버전 경고 | 구버전 참조가 있는 스킬은 경고와 함께 표시 |

### 도구 지식 이관 로드맵

| 정보 | 현재 위치 | 원칙상 위치 | 시기 |
|------|----------|------------|------|
| 스킬 카탈로그 | 복리엔진 | 복리엔진 | 현재 |
| MCP 서버 목록 | 복리엔진 | 복리엔진 | 현재 |
| CLI 도구 목록 | 없음 | 복리엔진 | Phase 1b |
| AI 모델 매핑 | Rona | 복리엔진 | Phase 2 (보류) |
| 도구 문서 싱크 | Rona | 복리엔진 | Phase 3 (보류) |

| 상황 | Rona 동작 |
|------|----------|
| 복리엔진 정상 | 스킬/MCP/CLI 정보를 실습에 포함 |
| 복리엔진 느림 (5초 초과) | 스킬 없이 실습 생성 (기존과 동일) |
| 복리엔진 장애 | 스킬 없이 실습 생성 (기존과 동일) |
| 연동 설정 안 됨 | 복리엔진 호출 자체를 건너뜀 |

## 7. 데이터 현황 — 통합이 유의미한가?

> 분석 기준일: 2026-03-10 · Rona 실습 130건 × 복리엔진 스킬 276개

### 실습 주제 분포

| 주제 | 실습 수 | 비율 |
|------|---------|------|
| 자동화/파이프라인 | 40 | 31% |
| AI API 활용 | 12 | 9% |
| 데이터 분석 | 10 | 8% |
| 업무 도구 연동 | 8 | 6% |
| AI 에이전트 | 7 | 5% |
| 기타 | 53 | 41% |

### 매칭 가능성

- **충분 (3개+ 스킬 매칭)**: 자동화, API, 에이전트, Python, GitHub, React, Claude, Vercel 등 14개 키워드
- **부족 (1~2개)**: PostgreSQL, Firebase, Stripe, Slack 등 9개
- **없음 (0개)**: Supabase, Webhook, 챗봇 등 6개
- **범용 스킬 ~40개**로 거의 모든 실습에 1개 이상 매칭 가능 (적중률 80%+ 추정)

### 가장 큰 갭: MCP 서버

- 현재 9개, 설치 명령어 0개, 활용 시나리오 0개
- 목표: 15개 이상 + 메타 정보 완비

### 통합 최소 기준

| 항목 | 최소 기준 | 현재 | 상태 |
|------|----------|------|------|
| MCP 서버 (메타 완비) | 15개 | 9개 (메타 없음) | 🔴 1순위 |
| 주제 특화 스킬 | 6개 중 4개+ | 0/6 | 🟡 2순위 |
| 범용 스킬 | 15개 이상 | ~40개 | ✅ 충분 |
