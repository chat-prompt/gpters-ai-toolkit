### 3. 에이전트 잔디의 고정 지표 일관성 수정

운영 점검 중 기간 토글 전후 에이전트 잔디가 `2,514건·최대 78건/일·52주`에서
`2,502건·최대 65건/일·51주`로 바뀌었다. 기간과 무관한 고정 지표가 몇 분 안에 달라졌으므로
GitHub 통계 API와 커밋 목록 폴백의 모집단 또는 서버리스 인스턴스별 캐시 차이를 확인해야 한다.

할 일:

1. 통계 API와 커밋 목록 폴백을 동일한 `[start, end)` 날짜 창으로 정규화한다.
2. 두 경로가 같은 fixture에서 같은 일별 시리즈를 만드는 계약 테스트를 추가한다.
3. 기간 변경 때 `usesPeriod: false` 패널을 다시 요청하지 않는다.
4. 필요하면 커밋 시리즈를 공유 캐시나 사전 계산 매니페스트로 옮긴다.

완료 기준:

- 7/30/90일 토글과 탭 이동으로 잔디의 기간·합계·최댓값이 바뀌지 않는다.
- 서로 다른 서버리스 인스턴스가 같은 기준 시각에 같은 시리즈를 반환한다.

진행 기록 (2026-08-24 완료):

- 통계 API와 커밋 목록 폴백을 오늘 포함 365일의 동일한 UTC `[start, end)` 창으로 정규화했다.
- 기간 변경 시 `usesPeriod: true` 패널만 다시 요청하도록 바꾸고 두 경로의 계약 테스트를 추가했다.
- localhost에서 30→7→90→30일 전환을 확인했다. 기간 지표는 `83→19→459→83건`으로 바뀌었고,
  사람 잔디 `459건·최대 111건/일`, 에이전트 잔디 `2,504건·최대 65건/일`, 양쪽 날짜 범위
  `2025-08-25~2026-08-24`는 유지됐으며 브라우저 콘솔 오류도 없었다.
- 운영에서 30→7→90일을 확인했고 사람 잔디 `459건·최대 111건/일`, 에이전트 잔디
  `2,519건·최대 78건/일`과 날짜·셀 스타일 배열이 유지됐다. P0-3과 P1-8의 기간 비연동 재요청
  제거는 완료로 본다.

### 4. 카탈로그 모집단 라벨과 활용률 명확화
