# 에이전트 관측 정확성 1~3차 작업

기준: main `68b6159de092a6d700e2c37c3c2f7e620f41e314`에서 분리한
`fix/agent-observability-accuracy`. 기존 작업 디렉터리와 성능 개선 브랜치는 수정하지 않았다.

## 1. 예약 실행 도구 문제

운영 기록에서 네이티브 셸 사용 불가, 접두사 없는 세션 도구 호출 실패와
예약 receipt의 `ok`가 동시에 확인됐다. 저장된 허용 목록에는 세션 도구가 있었다.
따라서 전체를 단순한 사용자 권한 부족이나 AITK 수집기 문제로 판정하지 않는다.

설치된 예약 정책 함수와 Claude CLI 옵션 변환 함수를 직접 실행했다.
유한 허용 목록은 유지되며 제한된 호출의 native 도구는 비어 있고,
세션 도구의 최종 이름은 `mcp__openclaw__...`였다. 실패 기록의 호출 이름과 다르다.
이는 도구 범위/이름 대조의 근거이며 당시 최종 MCP 연결 상태를 복원한 결과는 아니다.
운영 예약의 외부 전송 재실행, 권한 확대, 런타임 파일 패치는 수행하지 않았다.

**상태: 원인 범위 분류·정책 경로 재현·별도 격리 예약 probe 검증 완료. 원래 업무 재검증은 남음.**
실제 예약 실행기에서 기본 모델을 상속하고 `session_status`만 허용한 일회성 작업을 실행했다.
`claude-cli` 백엔드에서 `mcp__openclaw__session_status` 호출 1회와 오류 없는 결과를 확인했다.
예약 receipt는 ok, 외부 전달 비활성화, 작업 자동 삭제도 확인했다.
첫 probe는 잘못 지정한 모델 별칭 때문에 실행 전에 거절돼 제거했다. 모델 허용 정책은 수정하지 않았다.
원래 예약은 삭제됐으며 `current`/계정 정책 조건이었다. 성공한 probe는 operator가 만든
`isolated` 예약이므로 원래 업무가 복구됐다는 검증으로 확대하지 않는다.
원래 업무의 완료 조건은 scheduler/backend/owner/cap을 맞춘 무해한 probe와 영수증 대조다.
범용 절차는 [배포 프로토콜](../../infra/agent-telemetry/PROTOCOL.md#scheduled-task-preflight-and-completion)에 추가했다.
실제 호스트·사고 ID·원문 근거는 비공개 분석 기록에만 둔다.

## 2. 추적·집계 정확성

- `report_skill_outcome`의 시작/응답을 `execution-report` API 근거로 기록한다.
  스킬 결과 내용·명령·인증값을 이벤트에 복사하지 않는다.
- 같은 시각의 이벤트는 선행 관계와 같은 시도의 시작/종료 순서로 정렬한다.
  임의 UUID 문자열을 시간 순서로 사용하지 않는다. 잘못된 순환 관계도 무한 대기하지 않는다.
- 서버의 전체 합계 100개 제한을 agent/source별 최근 100개로 바꿨다. 한 소스가 다른 에이전트의 기록을 밀어내지 않는다.
  화면 필터 후 최근 100개를 페이지당 8개씩 표시한다. 생략된 이전 기록과 실패 필터의 범위를 명시한다.
  과거 전체 기록 탐색을 위한 서버 페이지네이션은 후속 확장 과제다.
- 등록 주기는 `max(5분, 주기×2)`, 주기 미등록만 12시간이다.
  판정에는 반올림 전 시각을 쓰고 소스 전체 상태는 각 수집기 지연을 반영한다.
- 별도 비공개 분석 계산기의 CLI/전달/도구 결과/롤오버를 `[since,until)`로 제한했다.
  CLI 파일 중복 조인·tool ID 중복을 방지하고 원천 없음/파싱 실패/시각 누락을 null과 상태로 표시한다.
  무시각 메타데이터는 도구 호출 집계에서 제외한다.
- 최신 session node는 과거 snapshot이 아니다. 기간 이후 업데이트된 snapshot 값은 제외하며
  과거 완전성을 보장하지 않는다고 표시한다. 현재 CLI binding으로 찾은 파일은 원천 시간을 다시 거른다.
- 늦게 전송된 task 이벤트를 현재 usage batch 창 안으로 강제하는 변경은 하지 않았다.

## 3. 표시와 수명주기

요약 줄과 비교 카드에 API 응답/프로세스 관측/자체 보고 근거를 표시한다.
전체 task 종료가 없으면 `종료 미관측`이며, 실행 종료만으로 작업 완료를 추정하지 않는다.
소스 능력은 미지원/미수집/불완전/지원으로 구분하고 도구 요약도 결측을 0으로 표시하지 않는다.
자동 receipt 검증이나 취소 전용 상태를 새로 구현했다고 해석하지 않는다.

## 검증 및 반영 범위

- CLI 관련 회귀 테스트 24개, 빌드 및 타입 검사 통과.
- AX 집계·타임라인·소스 상태 회귀 테스트 35개 통과. 수정 초기 웹 전체 단위 테스트 2,657개도 통과했다. 운영/공유 DB 변경 테스트 없음.
- 비공개 분석 계산기를 임시 SQLite/JSONL로 날짜 경계·중복·결측·파싱 실패·메타데이터에서 검증.
- 동일 계산기를 실제 호스트 하루 기록에 읽기 전용 실행: 39개 CLI 파일,
  도구 호출 1,076건, 파싱 실패/대상 시각 누락 0건. 전달/도구 결과 원천은 미수집(null).
  이 값은 현재 binding으로 찾은 범위이며 해당 기간 모든 과거 세션의 완전한 목록을 뜻하지 않는다.
- 로컬 Next 개발 서버에서 합성 데이터로 밝은/어두운 테마와 좁은 레이아웃을 직접 확인.
  테스트 전용 페이지는 배포 코드에서 제거한다.
- 웹 전체 타입 검사에는 기존 테스트 fixture 오류가 남아 있다. 변경한 제품 코드의 오류는 없었다.
- CLI 버전은 0.7.15로 준비했다. npm 발행·운영 배포·수집기 업그레이드와 실제 새 보고 대조는 별도 단계다.
