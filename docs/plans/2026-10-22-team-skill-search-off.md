## 2. 9/14 #139에서 바뀐 코드

Rona Coach 인터뷰에 `<team-skills>` 안내가 사용자 입력처럼 섞이는 문제(DEV-4377)를 고친 PR이다. 같은 훅이 세션 수 세기도 같이 하고 있어서 대화용 훅과 보고용 훅을 나눴다.

- `plugin.json`: `UserPromptSubmit` 훅 등록을 지웠다.
- `scripts/skill-search.sh`: 안내를 출력하던 48줄을 지우고 `exit 0`만 남겼다.
- `skills/skill-suggest/SKILL.md`: 설명을 "새 작업/주제 변경 시 팀 스킬을 자동 검색합니다"에서 "사용자가 팀 스킬이나 플러그인 검색을 요청했을 때 관련 스킬을 검색합니다"로 바꿨다.
- 안내를 대신할 다른 방법은 넣지 않았다.

그래서 0.1.24~0.1.31에서는 사용자가 "스킬 찾아줘"라고 하거나 AI가 스스로 `aitk search`를 할 때만 팀 스킬이 쓰인다.

## 3. 0.1.20 사용자에게는 왜 안내가 남아 있었나

0.1.20의 `auto-update.sh`는 `marketplaces/gpters-marketplace` 폴더만 찾는다. 실제 폴더 이름은 `chat-prompt-gpters-ai-toolkit`이라 업데이트가 아무 말 없이 건너뛰어졌다. #139에서 고쳤지만 고친 코드가 새 버전 안에 있어서 0.1.20은 스스로 올라가지 못한다. 그래서 9/14 뒤에도 0.1.20 사용자는 안내를 받았다. 재민 검색 기록이 9/14 뒤에도 이어진 것도 이 때문이다.

## 6. 정한 방식

PreToolUse 훅(`scripts/skill-gate.sh`)이 메시지마다 AI가 처음 도구를 쓰기 전에 한 번 막는다.

- 새 세션, `/clear`, 30분 넘게 쉰 뒤 첫 메시지: `aitk search`를 해야 넘어간다.
- 그 밖의 메시지: 새 작업이면 검색하고 같은 작업의 후속이면 `echo aitk:same-task`로 답해야 넘어간다. 검색은 강제하지 않고 판단만 강제한다.
- "계속", "커밋해" 같은 뻔한 후속 메시지와 도구를 쓰지 않는 답변은 막지 않는다.
- 매 메시지 안내(UserPromptSubmit)도 다시 붙인다.
- `AITK_SKILL_GATE=0`은 훅을, `AITK_SKILL_HINT=0`은 안내를 끈다. Rona Coach처럼 안내가 섞이면 안 되는 곳에서 쓴다.

넣지 않기로 한 방식:

- 매 메시지 서버 검색: 비용이 든다.
- 스킬 목록을 하루 한 번 받아 두고 단어로 맞추기: 하지 않기로 했다.

## 7. 평소 환경 실험 (10/22)

사용자 설정·플러그인·훅을 모두 켜고 빈 폴더에서 돌렸다. 세션마다 메시지 3개(새 작업 → "좋아, 그대로 계속 진행해줘" → 다른 작업)를 보냈다. 작업 쌍 10개를 3번씩 돌려 30세션씩이다. aitk 실행과 쓰기 가능한 외부 도구는 막고 검색 시도만 셌다.

| 메시지 | 안내만 | 안내 + 훅 |
| -- | -- | -- |
| 첫 작업 | 27/30 | 30/30 |
| 후속 ("계속 진행해줘") | 0/30 | 5/30 |
| 작업이 바뀐 요청 | 19/30 | 26/30 |

| 중간값·평균 | 안내만 | 안내 + 훅 |
| -- | -- | -- |
| 응답 시간, 첫 작업 | 33.4초 | 34.4초 |
| 응답 시간, 작업 바뀜 | 26.7초 | 29.6초 |
| 비용, 첫 작업 | $0.350 | $0.354 |
| 비용, 작업 바뀜 | $0.565 | $0.551 |

- 메시지당 1~3초 늘었고 비용은 거의 같았다.
- 후속 메시지 5건은 훅이 통과시킨 경우다. 실험에서 앞 검색이 막혀 AI가 다시 시도한 것으로 보인다.
- 작업이 바뀌었는데 놓친 4건은 AI가 도구를 쓰지 않고 말로만 되물은 경우다.
- 실험의 첫 메시지 검색률(27/30)이 실제 기록(10%)보다 훨씬 높다. 실제 레포와 실제 메시지에서는 훅의 효과가 더 클 것으로 본다.
