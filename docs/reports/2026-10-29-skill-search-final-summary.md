# 팀 스킬 검색 개선 최종 정리 (DEV-4697, 2026-10-29)

## 왜 시작했나

- 팀원 플러그인에서 메시지마다 붙던 검색 쪽지가 9/14부터 꺼져 있었다. 실제 기록에서 첫 메시지 검색률이 10% 정도였다.
- 검색을 해도 맞는 스킬이 위에 잘 나오지 않았다.
- 오래 안 쓴 스킬, 설명이 비었거나 서로 비슷한 스킬이 많아 검색 결과가 어지러웠다.

## 1. Claude가 검색을 하게 만들기

### 쪽지 다시 켜기 (`skill-search.sh`)

로나 코치 작업을 하던 중 쪽지 기능이 꺼져있었음. 
메시지마다 "팀 스킬을 검색하라"는 쪽지를 다시 붙였다. 문구에는 아래를 넣었다.

- 같은 프로젝트라도 새 결과물(화면, 글, 문서)을 만들라는 요청은 새 작업으로 보고 검색한다. (이전에는 같은 프로젝트라고 하면 스킬을 처음에 검색하고 중간에 ppt만들어주라 해도 스킬을 사용하지 않았음.)
- 검색어는 "하려는 일 + 재료·대상"으로 쓴다. 결과는 5개를 받는다. 작업 설명(`--context`)은 비우지 않는다. (기존에는 검색어가 2~4개의 단어로 구성되었는데 무엇을 할지와 재료, 대상을 넣어주니 유사도가 보다 잘 잡힘)
- 사용자가 팀 스킬이나 aitk 스킬을 쓰라고 하면 검색한다. (호출하면 무조건 검색)
- 재료가 없어 되물어야 할 때도 묻기 전에 먼저 검색한다. 맞는 스킬이 무엇을 물어야 할지 알려 준다.
   (ppt 만들어줘. -> 어떤 주제로? : 이 형태에서는 스킬을 검색하지 않아버림 
   하지만 스킬 검색을 강제하면서 주제, 스타일 묻는 것도 스킬 안에 있는 내용으로 해결)
### 강제 훅 (`skill-gate.sh`, 새 파일)

쪽지만으로는 Claude가 검색을 자주 건너뛰어서 넣었다(DEV-4700). Claude가 파일을 읽거나 명령을 실행하는 등 실제 작업을 시작하려는 순간에 한 번 멈춰 세우고 먼저 검색하게 한다.

- 새 세션, `/clear`, 30분 넘게 쉰 뒤 첫 메시지에서는 팀 스킬을 검색해야 작업을 시작할 수 있다.
- 그 밖의 메시지에서는 새 작업인지 같은 작업인지 먼저 답하게 한다. 새 작업이면 검색한다. 같은 작업이면 그대로 이어서 한다. (이 부분이 토큰이 걱정되긴 하나, 빼도 위 쪽지만으로도 성능 기존보다는 훨씬 좋음)
- 작업을 시작하지 않고 답만 하는 경우(되묻기, 짧은 설명)에는 멈춰 세울 수 없다.
- "계속", "커밋해" 같은 뻔한 후속 메시지와 5글자 미만 메시지("그래", "ㅇㅋ")는 막지 않는다. 
- 막을 때 보여 주는 안내도 쪽지와 같은 검색어 규칙으로 맞췄다.
- `AITK_SKILL_GATE=0`이면 꺼진다.

## 2. 맞는 스킬이 위에 나오게

- 스킬 임베딩에는 이름·설명·태그만 넣고 본문은 뺐다.
- 검색어에 스킬 ID나 이름이 그대로 있으면 +0.3을 주고 맨 앞에 놓는다.
- 태그에 주던 가산점은 없앴다. (태그로 가산점을 주는 방식이 오히려 별로였음.)
- 코드는 `packages/lib/src/search/embedding.ts`, `vector-search.ts`, 단위 테스트 2개. aitk2 커밋 78554b5b.

| 시험 | 전 | 후 |
|---|---|---|
| 41문항, 맞는 스킬이 1위 | 26 | 32 |
| 팀 시험셋 115문항, 맞는 스킬이 상위 5개 안 | 106 | 110 |
임베딩에서 1위를 하는건 의미가 없음. 어차피 추후 AI가 5개 중에서 선택을 하기 때문에.

## 4. 마지막 실험: 쪽지만 vs 쪽지 + 강제 훅

10/22 실험과 같은 방식이다. 세션마다 메시지 3개(새 작업 → "좋아, 그대로 계속 진행해줘" → 다른 작업)를 보냈다. 로컬 aitk2로 실제 검색과 불러오기가 되게 했다. 작업 쌍 10개를 한 번씩 돌렸다(Sonnet).

| 메시지 | 쪽지만 | 쪽지 + 강제 훅 |
|---|---|---|
| 첫 작업 | 검색 7/10 · 불러옴 5 | 검색 10/10 · 불러옴 7 |
| 후속 | 0/10 | 0/10 |
| 작업이 바뀐 요청 | 검색 8/10 · 불러옴 4 | 검색 10/10 · 불러옴 4 |

- 되묻던 요청(슬라이드 개요, 실습 문제, 인스타 문구)도 묻기 전에 검색했다.
- 훅이 막은 건 첫 작업 4건이다. 내 컴퓨터에 깔린 스킬(site-check, systematic-debugging)을 먼저 부르거나, 폴더부터 둘러본 경우였다.
- 시간은 막힌 첫 작업 메시지에서 약 20초 늘었다. 후속과 작업 바뀜에서는 거의 같았다.
