# Codex 팀 스킬 검색 쪽지 재실험 (2026-10-28)

Codex 실험에서 매 메시지에 붙어야 할 검색 안내(`<team-skills>`, 이하 쪽지)가 빠져 있었다. Claude 실험과 입력 조건이 달랐으므로, 같은 메시지에 쪽지를 붙여 다시 실행했다.

사용자가 이전에 받은 표와 같은 **검색 시도 기준**으로 보면, B(대화 중 새 작업·사용법 질문)는 **5/10 → 8/10**, P(정답 있는 메시지)는 **5/15 → 15/15**다. P의 검색 누락은 이번 재실험에서 관찰되지 않았지만, B는 2건이 남았다. 이전 표의 **“P에서 스킬 적용까지 간 건 2개”는 이번에 재채점하지 않았다. 검색 15/15를 스킬 적용 15/15로 읽으면 안 된다.**

양쪽 모두 정상 완료한 동일 41건에서 기존 정답표와 일치한 검색 판단은 **35/41 → 39/41 · 참고**로 늘었다. 쪽지를 보완한 뒤 나아진 결과지만, 한 번씩 실행한 소규모 실험이라 변화가 모두 쪽지 때문이라고 확정할 수는 없다.

## 1. 무엇을 보완했나

기존 실행기 `codexrun/run.sh`는 이전 대화의 끝 6,000자와 새 사용자 메시지만 전달했다. Claude의 `apps/claude-code-plugin/scripts/skill-search.sh`가 출력하는 쪽지는 포함하지 않았다.

이번에는 실험 당시 Claude 훅의 CLI 분기에서 출력하는 쪽지 원문을 각 입력 마지막에 정확히 한 번 붙였다. 쪽지에는 직접적인 후속이 아니면 검색하라는 기준과 `aitk search` 실행 방법이 들어 있다. 쪽지 문구 자체를 새로 개선한 실험은 아니다.

| 조건 | 이전 | 이번 |
|---|---|---|
| 검색 쪽지 | 없음 | 모든 입력에 동일한 원문 1회 삽입 |
| 이전 대화 | 끝 6,000자를 문자열로 전달 | 동일 |
| 모델 | `gpt-6.1-sol` | 동일 |
| Codex CLI | `0.163.0` | 동일 |
| 설치 환경 | 프로젝트 AGENTS.md·Codex 플러그인 스킬, 사용자 전역 설정과 분리 | 동일한 방식으로 별도 작업 폴더 사용 |
| 검색 경로 | 로컬 aitk2 서버(3100)를 보는 CLI shim | 동일 |

처음에는 55건 전체를 대상으로 시작했다. 진행 중 사용자가 이전 실패 사례만 확인해도 된다고 요청해 기존 실행 큐를 중단하고, 남은 실행은 이전 검색 판단 실패 6건과 사용량 제한으로 중단된 13건으로 제한했다. 이미 완료한 정상 사례의 결과는 보존했다.

## 2. 전체 결과

### 이전에 사용자에게 제시한 표와 같은 기준: 검색 시도

아래 숫자는 **실제 검색 명령을 관찰한 메시지 수 / 그룹 전체 메시지 수**다. 검색 후 응답 생성 중 오류가 났더라도 관찰된 검색은 포함한다. 반대로 검색 전에 오류가 난 사례는 미검색 판단이 확인된 것으로 해석할 수 없다.

| 그룹 | 기대 동작 | 이전: 쪽지 없음 | 이번: 쪽지 있음 |
|---|---|---:|---:|
| A. 잡담·결과 알림 | 검색 안 함 | 검색 0/15 | 검색 0/15 |
| B. 대화 중 새 작업·사용법 질문 | 검색함 | **검색 5/10** | **검색 8/10** |
| F. 같은 작업의 후속 | 검색 안 함 | 검색 0/15 | 검색 0/15 |
| P. 정답 있는 메시지 | 검색함 | **검색 5/15** | **검색 15/15** |

- 이번 B의 `b51`은 검색 후 모델 수용량 오류가 났다. 검색 시도 표에는 포함하지만, 아래 정상 완료 기준 표에서는 제외한다.
- 이전 P의 15건 중 12건은 사용량 제한으로 중단됐다. 이전 검색 5건에는 검색 후 중단된 3건이 포함된다. 따라서 P의 5/15 → 15/15 변화에는 쪽지 보완과 사용량 제한 해소가 함께 섞여 있다.
- 이전에 보고된 P의 스킬 적용 2건은 이번에 같은 기준으로 재평가하지 않았다. **검색 유도 개선과 실제 적용 개선은 별개다.**

### 보조 비교: 정상 완료한 실행의 검색 판단

숫자는 **기존 정답표와 일치한 건수 / 정상 완료한 건수**다. 검색해야 하는 메시지는 검색했을 때, 검색하지 않아야 하는 메시지는 검색하지 않았을 때 맞은 것으로 센다.

| 메시지 종류 | 이전: 쪽지 없음 | 이번: 쪽지 있음 |
|---|---:|---:|
| 잡담·결과 알림 — 검색하지 않아야 함 | 15/15 | 15/15 |
| 새 작업·사용법 질문 — 검색해야 함 | 5/10 | 7/9 |
| 같은 작업의 후속 — 검색하지 않아야 함 | 14/14 | 15/15 |
| P. 정답 있는 메시지 | 2/3 | 15/15 |
| **전체 정상 완료 사례** | **36/42** | **52/54** |
| **양쪽 모두 정상 완료한 동일 사례만 비교** | **35/41** | **39/41** |

- 이전에는 55건 중 13건이 사용량 제한으로 중단됐다. 미검색이나 판단 실패로 세지 않았다.
- 이번에는 55건 중 54건이 정상 완료됐다. `b51`은 검색 명령이 정상 종료한 뒤 모델 수용량 오류로 중단돼 전체 완료 기준 집계에서 제외했다. 이전에는 정상 통과한 사례여서 실패 사례만 확인하자는 요청 이후 재시도하지 않았다.
- 따라서 전체 결과의 분모가 다르다. 보완 전후 변화는 동일한 41건의 **35/41 → 39/41 · 참고**를 우선해서 본다.
- 같은 41건에서 이전에 맞았던 35건은 이번에도 맞았다.

## 3. 이전 실패 19건의 재검증

| 이전 상태 | 건수 | 이번 결과 |
|---|---:|---|
| 검색 판단 실패 | 6 | **4건 개선, 2건 미해결** |
| 사용량 제한으로 중단 | 13 | **13건 모두 정상 완료, 기존 검색 정답표와 일치** |

사용량 제한 13건은 이전에는 판단 결과가 없었던 사례다. 이를 검색 판단이 개선된 13건으로 해석하지 않는다.

검색 판단 실패 6건의 변화는 다음과 같다. 요청은 내용을 요약해 적었다.

| 사례 ID | 요청 | 이전 검색 | 이번 검색 | 결과 |
|---|---|---|---|---|
| `b6` | 부품목록 엑셀로 Streamlit 재고 조회 화면 만들기 | 안 함 | 함 | 개선 |
| `b214` | image-assets에 그림 주문 보내기 | 안 함 | 함 | 개선 |
| `b219` | 렌더 포맷 mp4·mov 중 무엇이 나은지 질문 | 안 함 | 함 | 개선 |
| `46` | 세션의 성공·실패 사례로 하네스·훅을 개선하는 스킬 만들기 | 안 함 | 함 | 개선 |
| `b30` | 엑셀로 한눈에 보는 사이트 만들기 | 안 함 | 안 함 | 파일 위치를 되물으며 검색을 건너뜀 |

`46`은 이번 첫 시도에서도 검색했지만 이후 서버 수용량 오류로 중단됐다. 첫 시도 로그를 보존한 뒤 재시도했고, 재시도도 검색 후 정상 완료했다.

남은 두 사례는 쪽지가 실제로 붙어 있었는데도 검색하지 않았다. 쪽지 전달 누락과 별개로, 이전 코칭 흐름을 따르며 새 작업의 검색을 건너뛰는 문제가 남아 있다.

## 4. 결과가 좋아 보이는 이유와 해석의 범위

**52/54만으로 검색 문제가 거의 해결됐다고 보기는 어렵다.** 이번 정상 완료 54건 중 30건은 검색하지 않아야 하는 잡담·결과 알림·후속 요청이다. 이 30건은 모두 검색하지 않았다. 또 이전 사용량 제한으로 빠졌던 13건이 이번에 정상 완료돼, 전체 집계에는 서로 다른 사례가 포함된다.

이번에 확인한 핵심은 기존 검색 판단 실패 6건 중 4건이 검색하도록 바뀌었고, 비교 가능한 기존 정답 35건에서 회귀를 관찰하지 않았다는 점이다.

남은 확인 범위는 B의 `b30`·`b229` 검색 누락 원인과 P의 실제 스킬 적용 여부다. “검색 문제와 적용 문제 모두 해결, 배포만 남음”으로 완료 처리하면 안 된다. 추가 확인이 필요하면 이미 있는 로그부터 검토하고, 전체 실행을 다시 반복하기보다 미해결 사례만 다룬다.

다음 범위는 확인하지 않았다.

- 실행마다 모델 응답이 달라질 수 있다. 쪽지 유무를 무작위로 배정해 반복 측정한 실험은 아니다.
- 기존 정답표를 그대로 사용했다. 검색해야 한다는 정답 자체를 새로 독립 평가하지 않았다.
- 이전 대화를 문자열로 재구성한 독립 실행이다. 실제 연속 대화에서 네이티브 Codex 훅이 매번 동작하는지 검증한 것은 아니다.
- 검색 결과의 적합성, 스킬 선택·로드·적용 품질, 최종 산출물 품질은 이번에 다시 채점하지 않았다.

## 5. 근거와 검증

실험 원자료는 로컬 형제 작업 폴더에 보관했다. 아래 위치는 이 저장소 루트 기준이며, 원자료가 저장소에 함께 커밋된 것은 아니다.

```text
../aitk2/experiments/2026-10-27-step34/
├── codexrun/                  # 이전 실행기와 출력
└── codexrun-hint-rerun/
    ├── RESULTS.md            # 실행 시 정리한 결과
    ├── items.json            # 메시지·이전 대화·기존 정답표
    ├── hint.txt              # 삽입한 쪽지 원문
    ├── prompts/              # 실제 입력 55개
    ├── out/                  # 실행 로그와 최종 답변
    ├── first-attempt/46.*    # 서버 오류가 난 첫 시도
    ├── failed-only-ids.txt   # 이전 실패 19건
    ├── rows.json             # 사례별 집계
    ├── summary.json          # 실패 재검증 요약
    └── tally.py              # 집계 및 명령 판별 자체 검사
```

- 입력 55개 모두 쪽지가 정확히 한 번 있고 `hint.txt`와 동일한지 assert로 검사했다.
- 모델·CLI 버전은 이전·이번 세션 메타데이터로 확인했다.
- 검색 여부는 답변의 주장 대신 실제 완료된 `aitk search` 명령으로 집계했다. 명령 판별에는 검색 명령과 단순 출력·스킬 파일 읽기를 구분하는 자체 검사가 있다.
- 이전 실패 19건이 모두 정상 완료됐는지, 판단 실패 6건 중 개선 4건·미해결 2건인지 원자료와 대조했다.
- 제품 코드 수정이나 운영 배포는 하지 않았다.
