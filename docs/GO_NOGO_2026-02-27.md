## 1. 결론: No-go — 필수 조건 전부 미충족, 퍼블릭 확장 불가

### 1-0. 3/6 측정: No-go 유지 (필수 0/3, 전체 3/6)

3/4 대비 2일간의 추가 데이터가 축적되었으나, **필수 3개 조건 모두 여전히 미충족**이다.

- **추천 적중률 15.5%** (3/4: 15.3%) — 0.2%p 미세 상승. 목표(30%)의 절반. 2주간 구조적 개선 없이는 변화 없음이 확인됨.
- **검색 무결과율 25.0%** (3/4: 21.7%) — 오히려 3.3%p 악화. 표본 56건으로 최소 기준(100건) 미달이나, 추세는 부정적.
- **검색 속도 P50 2,501ms** (3/4: 2,499ms) — 사실상 동일. 임베딩 캐싱/최적화 없이는 개선 불가.

가산 조건 3개는 모두 계속 초과 달성 (발견의 가치 14건, 외부 스킬 10건, 시간 절약 247건). **"찾기만 하면 쓴다"는 전제는 유효하나, "잘 찾아주지 못한다"가 근본 문제.**

### 1-1. 3/4 중간 판정: No-go (필수 0/3, 전체 3/6)

표본이 충분해진 지표(n=491)에서 **추천 적중률이 15.3%로 목표(30%)의 절반**에 그쳤다. 2/27에 28.8%(n=56)였던 수치가 표본 증가와 함께 하락한 것은, 초기 소표본이 과대 추정이었음을 보여준다. 검색 속도(P50 2,499ms)도 목표(2,000ms)를 여전히 초과한다.

가산 조건 3개(발견의 가치 11건, 외부 스킬 9건, 시간 절약 238건)는 모두 초과 달성하여 **플랫폼의 기본 가치는 작동**하고 있으나, 핵심 품질 지표가 미달인 상태에서 퍼블릭 확장은 시기상조다.

### 1-2. 다음 단계

3/21 최종 판정까지 남은 2.5주간 집중할 사항:
1. **추천 적중률**: 쿼리 생성 로직 근본 개선 (userContext 활용도 검증, 임베딩 모델 교체 검토)
2. **검색 속도**: P50 2,000ms 이하로 개선 (캐싱, 임베딩 최적화)
3. **사용량 회복**: 2/27 이후 일일 사용량 급감 → 내부 활성화 방안 필요

### 각 조건별 측정 SQL

#### 조건 1: 추천 적중률 (search→load 전환율)

```sql
-- 분자: 검색 결과로 노출된 스킬을 같은 세션에서 조회(load)한 (세션×스킬) 쌍 수
-- 분모: 검색 결과로 노출된 전체 (세션×스킬) 쌍 수
-- 범위: skill_events 테이블, 최근 30일
WITH search_skills AS (
  SELECT DISTINCT session_id, skill_id
  FROM skill_events
  WHERE action = 'search' AND created_at >= NOW() - INTERVAL '30 days'
),
loaded_skills AS (
  SELECT DISTINCT session_id, skill_id
  FROM skill_events
  WHERE action = 'load' AND created_at >= NOW() - INTERVAL '30 days'
)
SELECT
  COUNT(*) AS total_recommendations,
  COUNT(*) FILTER (WHERE ls.skill_id IS NOT NULL) AS matched_loads,
  ROUND(COUNT(*) FILTER (WHERE ls.skill_id IS NOT NULL)::numeric / NULLIF(COUNT(*), 0) * 100, 1) AS hit_rate_pct
FROM search_skills ss
LEFT JOIN loaded_skills ls USING (session_id, skill_id);
```

#### 조건 2: 검색 무결과율

```sql
-- 훅(skill-suggest) 경유 검색 중 유효 결과 없는 비율
-- "유효 결과 없음" = 결과 0건 OR top score < 0.40
-- 범위: mcp_audit_logs, referral_source='suggest' OR _source='skill-suggest'
SELECT
  COUNT(*)::int AS total_searches,
  COUNT(*) FILTER (
    WHERE search_results IS NULL
      OR jsonb_array_length(search_results) = 0
      OR (search_results->0->>'score')::float < 0.40
  )::int AS zero_result,
  ROUND(
    COUNT(*) FILTER (
      WHERE search_results IS NULL
        OR jsonb_array_length(search_results) = 0
        OR (search_results->0->>'score')::float < 0.40
    )::numeric / NULLIF(COUNT(*), 0) * 100, 1
  ) AS zero_result_pct
FROM mcp_audit_logs
WHERE created_at >= NOW() - INTERVAL '30 days'
  AND (tool = 'search_plugins' OR tool = 'semantic_search')
  AND (
    referral_source = 'suggest'
    OR request_params->'params'->'arguments'->>'_source' = 'skill-suggest'
  );
```

#### 조건 3: 발견의 가치 (full funnel 완주)

```sql
-- search → load → (apply OR deploy) 모두 발생한 (세션×스킬) 쌍
WITH funnel AS (
  SELECT session_id, skill_id,
    bool_or(action = 'search') AS searched,
    bool_or(action = 'load') AS loaded,
    bool_or(action IN ('apply', 'deploy')) AS converted
  FROM skill_events
  WHERE created_at >= NOW() - INTERVAL '30 days'
  GROUP BY session_id, skill_id
)
SELECT COUNT(*) AS full_funnel_count
FROM funnel
WHERE searched AND loaded AND converted;
```

#### 조건 4: 검색 속도 P50

```sql
SELECT
  ROUND(PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY response_time))::int AS p50_ms,
  COUNT(*)::int AS sample_count
FROM mcp_audit_logs
WHERE created_at >= NOW() - INTERVAL '30 days'
  AND (tool = 'search_plugins' OR tool = 'semantic_search')
  AND response_time IS NOT NULL;
```

```sql
-- 현재는 수동 확인: catalog_items.author_id로 외부 판단
-- 자동화 보류 (외부/내부 구분 로직 미구현)
```

#### 조건 6: 시간 절약 사례 (apply + deploy 누적)

```sql
SELECT
  COUNT(*) FILTER (WHERE action = 'apply')::int AS apply_count,
  COUNT(*) FILTER (WHERE action = 'deploy')::int AS deploy_count,
  COUNT(*)::int AS total_positive
FROM skill_events
WHERE created_at >= NOW() - INTERVAL '30 days'
```

## 6. 근본 원인 분석 — 왜 필수 조건이 안 되는가

### 6-1. 추천 적중률 15.3% (목표 30%) — 쿼리-스킬 간 의미 격차

스킬별 S→L%(search→load) 편차가 크다:
- **높은 적중**: gpters-revenue-query(100%), utm-builder(83%), gpters-renewal-interview(67%), gpters-product-mixpanel(64%)
- **낮은 적중**: write-post(21%), gpters-product-coupon(18%), devlog-to-issue(13%), study-application-bettermode-publish(10%), gpters-free-purchase(6%)

높은 적중 스킬은 **이름만으로 용도가 명확**하다. 낮은 적중 스킬은 검색에서 노출되지만 이름/설명이 현재 작업과 관련 있어 보이지 않아 클릭하지 않는 패턴.

**핵심 문제**: AI가 생성한 검색 쿼리가 너무 넓어서 관련성 낮은 스킬까지 노출됨. 점수 필터(0.40)가 느슨하여 491개 추천 중 실제 관련 있는 것은 75개뿐.

### 6-2. 검색 속도 P50 2,499ms (목표 2,000ms) — 임베딩 API 병목

OpenAI 임베딩으로 전환했으나 P50이 2,674ms → 2,499ms로 175ms만 개선. 주요 병목이 임베딩 생성 자체가 아닌 네트워크 레이턴시 + DB 쿼리 결합에 있을 가능성.

### 6-3. 사용량 급감 — 내부 채택 한계

2/27 이후 일일 요청이 97% 감소. 44명의 고유 사용자 중 지속 사용자는 2~3명. 스킬 자동 추천이 "있으면 좋은 것" 수준이지 "없으면 안 되는 것"이 아님을 시사.
