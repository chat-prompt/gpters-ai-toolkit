# 생산성 복리 엔진 프로젝트

> 팀의 AI 코딩 노하우를 축적하고, 필요한 순간에 자동으로 꺼내주는 플랫폼 → 지피터스 커뮤니티 전체로 확장

---

## 1. 이슈

팀원들이 만든 AI 코딩 스킬(73개)이 공유 플랫폼에 있지만, 필요한 순간에 찾지 못해 활용되지 않고 있음.

- 스킬 이름이 모호하고 중복 → 노출돼도 100% 무시되는 스킬 4개
- 자동 검색과 수동 검색이 섞여 측정이 왜곡됨 (전체 무결과율 90% vs 실제 수동 무결과율 27%)
- 그러나 결과가 나오면 전환율 66.7%, 조회→배포 22.2% → **찾기만 하면 쓴다**

---

## 2. 해결 방안

내부 검색 품질을 검증한 뒤, 지피터스 커뮤니티에 스킬 검색/설치/업로드를 퍼블릭 오픈하여 "AI 코딩 스킬 허브"로 확장

---

**내부 품질 검증 (Phase 1~3)**

|------|------------|-------------|-----------|
| 수동 검색 무결과율 | ~27% | **10%** ✅ | 10% 유지 |
| 검색→조회 전환율 | 5.1% | **15%** | **25%** |
| 전체 무결과율 (자동 포함) | 90.4% | **50%** | **30%** |
| 자동 추천→조회 전환율 | 측정 불가 | 측정 가능 ✅ | **20%** |

| 지표 | 오픈 시 | 1주 후 목표 |

## 4. 리스크 및 가설

| # | 리스크 | 가설 |
|---|--------|------|
| 1 | 스킬 이름이 모호/중복 → 노출돼도 무시 | 직관적 네이밍 + 중복 정리로 클릭율 개선 |
| 2 | 수동 검색에서 관련 스킬 없는 검색어 존재 | 무결과 검색어에 대응하는 스킬 추가/보강으로 무결과율 하락 |

| 5 | 커뮤니티 스킬 업로드 시 저품질 스킬 축적 | description 필수 + content 200자 이상 자동 검증. 이후 사용량 기반 랭킹 도입 |

# 상세 이슈

## Phase 1 완료 상세

### DEV-2996: `_source` 태깅 및 측정 분리

**문제:** skill-suggest 훅이 모든 프롬프트마다 `semantic_search`를 호출하면서 `_source` 태깅 없이 기록됨. 전체 무결과율 90%가 자동 검색에 의한 허수.

**근본 원인:** `packages/lib/src/mcp/tools.ts`의 `semantic_search` inputSchema에 `_source` 프로퍼티가 누락. 파이프라인(`types.ts` → `handlers.ts` → `route.ts` → `mcp-audit.ts`)은 이미 구현돼 있었으나 스키마에서 막혀 클라이언트가 파라미터를 전달할 수 없었음.

**수정:** `tools.ts`에 `_source` 프로퍼티 추가 (1줄 수정). `analyze-mcp-usage.mjs` 스킬 생성으로 source별 분리 분석 가능.

### DEV-2997: 스킬 네이밍/설명 개선

**문제:** 100% 무시 스킬 4개 — `update-proj`(5회), `update-init`(4회), `initiative-project-update`(2회), `interview-prd`(2회)

**분석 결과:** 리니어 스킬 3개는 중복이 아닌 역할 구분 확인.
- `update-proj`: 주간 프로젝트 보고 (소유: 송다혜)
- `update-init`: 주간 이니셔티브 보고 (소유: 송다혜)
- `initiative-project-update`: 기획서 작성 (소유: 현진우)

**완료:**
- `initiative-project-update` → "Linear 프로젝트/이니셔티브 기획서 작성"으로 이름 변경
- `update-proj`, `update-init`은 소유자(송다혜)에게 개선 제안 전송 (대기 중)

### DEV-2998: 수동 검색 무결과 콘텐츠 갭 보충

**문제:** 수동 검색 무결과 검색어 6건 (solapi, portone, devlog, Linear 이슈, airtable, usage tracking)

**분석 결과:** 재검증 시 대부분 현재 검색 결과 반환됨. 남은 이슈:
- `gpters-sender`: description 비어있음 → 소유자에게 개선 제안
- `devlog-to-issue` / `linear-devlog-to-issue`: 완전 중복 → 정리 개선 제안
- 개선 제안 4건 대기 중 (송다혜 검토 필요)

## Phase 4 상세: 커뮤니티 오픈

### 스킬 현황 (DB content 기반 분석)

| visibility | 개수 | 실제 내용 |
|------------|------|----------|
| `public` | 42개 | 범용 개발 스킬 — TDD, 코드리뷰, React, Next.js, Git, 디버깅 등 |
| `shared` | 27개 | 대부분 GPTers 내부 종속 |
| `private` | 4개 | GPTers 결제/Analytics/발송 |

**shared 27개 분석:**

| 분류 | 개수 | 내용 |
|------|------|------|
| GPTers 서비스 종속 | 15 | 상품/쿠폰, 환급, CDN, Internal API, DB 접근, 디자인 시스템, 스터디 지원서 등 |
| Linear + GPTers 관례 종속 | 9 | `create-issue`, `update-proj/init`, `devlog-to-issue` 등 |
| **범용 (public 전환 가능)** | **3** | `excalidraw-diagram`, `neon-postgres`, `vercel-deploy-claimable` |

→ 커뮤니티 즉시 제공: 42 + 3 = **45개**

### 필요 개발 항목

| 항목 | 현재 | 변경 | 난이도 |
|------|------|------|--------|
| 인증 | `@gpters.org` only | Google 전체 계정 허용 | 중간 |
| 스킬 가시성 | `visibility` 필드 존재 | 커뮤니티에는 `public`만 노출 | 낮음 |
| 스킬 업로드 | `deploy_skill` 내부 전용 | 커뮤니티도 사용 가능, 자동 `public` + 본인 소유 | 중간 |
| API 권한 | role 구분 없음 | `community` role 추가 | 중간 |
| 품질 관리 | 없음 | description 필수 + content 200자 이상 | 낮음 |
| 사용량 모니터링 | 내부만 | 커뮤니티 사용량 별도 추적 | 낮음 |
