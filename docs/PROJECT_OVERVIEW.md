# 생산성 복리 엔진 프로젝트

> 팀의 AI 코딩 노하우를 축적하고, 필요한 순간에 자동으로 꺼내주는 플랫폼

---

## 1. 이슈

팀원들이 만든 AI 코딩 스킬(72개)이 공유 플랫폼에 있지만, 필요한 순간에 찾지 못해 활용되지 않고 있음.

- 스킬 이름이 모호하고 중복(update-proj, update-init, initiative-project-update) → 노출돼도 100% 무시
- 결과가 나오면 세션 전환율 66.7%, 조회→배포 22.2%로 **찾기만 하면 쓴다**

---

## 2. 1줄 해결 방안

측정 왜곡을 바로잡고, 스킬 네이밍/콘텐츠 갭을 개선하여 "검색하면 원하는 스킬이 나오는" 상태를 만든 뒤, 외부 서비스화 Go/No-go를 판단

---

## 3. 목표

**결과물**
- 수동 검색 무결과율 10% 이하 + 검색→조회 전환율 15% 이상 달성
- Phase 3에서 외부 서비스화 Go/No-go 판단 근거 및 방향성 문서 산출

**지표**

| 지표 | 현재 (2/20) | Phase 1 목표 | Phase 2 목표 |
|------|------------|-------------|-------------|
| 수동 검색 무결과율 | ~27% | **10%** | 10% 유지 |
| 검색→조회 전환율 | 5.1% | **15%** | **25%** |
| 조회→배포 전환율 | 22.2% | 22% 유지 | **25%** |
| 전체 무결과율 (자동 포함) | 90.4% | — | **30%** |
| 자동 추천→조회 전환율 | 측정 불가 | 측정 가능 | **20%** |

---

## 4. 리스크 및 가설

**리스크 1:** 스킬 이름이 모호하고 중복되어, 검색 결과에 노출돼도 사용자가 무시한다 (100% 무시 스킬 4개 존재)

→ **(가설 1)** 직관적 네이밍 + 중복 정리를 하면, 1위 노출 시 클릭율이 code-reviewer 수준(67%)에 근접할 수 있다

**리스크 2:** 수동 검색에서 관련 스킬이 없는 검색어(solapi, portone, devlog 등)가 존재하여 무결과가 발생한다

→ **(가설 2)** 무결과 검색어 8건에 대응하는 스킬을 추가/description 보강하면, 수동 무결과율을 낮출 수 있다

**리스크 3:** MCP 프로토콜이 표준이 되지 않거나, Claude Code가 자체 팀 공유 기능을 출시하면 경쟁 우위가 소멸한다

→ **(가설 3)** 멀티도구 지원(Claude Code, Codex, OpenCode)이 차별점이므로, 특정 도구 종속을 회피하는 전략이 리스크를 완화한다

## 5. 진행 방안

### Phase 1: 측정 기반 확립 (~3/7)

> 잘못된 지표로는 올바른 판단을 할 수 없다

| 이슈 | 우선순위 | 마감 | 담당 | 내용 |
|------|---------|------|------|------|
| [DEV-2996](https://linear.app/geniefy/issue/DEV-2996) | Urgent | 3/3 | 진우 | `_source` 태깅 적용 → 자동/수동 검색 분리 측정 |
| [DEV-2997](https://linear.app/geniefy/issue/DEV-2997) | High | 3/5 | 진우 | 스킬 네이밍/설명 개선 및 리니어 스킬 3개 중복 정리 |
| [DEV-2998](https://linear.app/geniefy/issue/DEV-2998) | High | 3/7 | 진우 | 수동 검색 무결과 콘텐츠 갭 보충 (8건 대응) |

**DEV-2996 상세:**
- `apps/claude-code-plugin/skills/skill-suggest/SKILL.md` 수정 — semantic_search 호출 시 `_source: 'skill-suggest'` 필수 전달
- `packages/lib/src/mcp/` — `_source` 파라미터를 audit log의 `referral_source` 필드에 저장
- `analyze-mcp-usage.mjs` — source별 분리 분석 섹션 추가

**DEV-2997 상세:**
- 100% 무시 스킬: update-proj(5회), update-init(4회), initiative-project-update(2회), interview-prd(2회)
- 리니어 스킬 3개 역할 분석 → 통합 또는 이름 구분 (예: `linear-weekly-update`, `linear-initiative-report`)
- description에 "어떤 상황에서 쓰는 스킬인지" 명시

**DEV-2998 상세:**

| 무결과 검색어 | 대응 방안 |
|-------------|----------|
| solapi, SMS, 알림톡 | 신규 스킬 추가 |
| portone, 결제 API | 기존 스킬 description 보강 |
| devlog, 개발 로그 | devlog-to-issue 스킬 매칭 확인 |
| Linear 이슈 생성 | DEV-2997 네이밍 개선으로 해결 |
| airtable 연동 | 기존 airtable-integration 매칭 확인 |
| 환불 환급 자동화 | 기존 refund-processor 매칭 확인 |
| usage tracking | 분석 관련 스킬 매칭 개선 |

### Phase 2: 추천 고도화 (~3/21)

> 매 프롬프트마다 검색하는 건 스팸이다. 맥락을 이해하고 필요한 순간에만 추천해야 한다

| 이슈 | 우선순위 | 마감 | 담당 | 내용 |
|------|---------|------|------|------|
| [DEV-2999](https://linear.app/geniefy/issue/DEV-2999) | Medium | 3/14 | 진우 | skill-suggest 훅 스마트 추천 |

**DEV-2999 상세 (DEV-2996 완료 후 착수):**

| 현재 | 개선 |
|------|------|
| 모든 프롬프트 → 검색 | 새 작업/주제 변경 시에만 검색 |
| 프롬프트 전체를 검색어로 | 핵심 키워드 추출 후 검색 |
| 결과 무조건 노출 | score threshold 0.65 이상만 추천 |

추가 작업:
- `analyze-mcp-usage` 스킬로 개선 효과 반복 측정
- 팀원 대상 사용성 피드백 수집

### Phase 3: 외부 서비스화 판단 (~3/31)

> 내부에서 안 쓰이는 제품을 밖에 내놓지 않는다

Phase 1-2 결과 기반 Go/No-go 판단.

**Go 조건 (3개 이상 충족 시):**
- [ ] 수동 검색 무결과율 **10% 이하**
- [ ] 검색→조회 전환율 **15% 이상**
- [ ] 팀원 과반 **주 1회 이상** 스킬 사용
- [ ] 외부 팀 2곳 이상 **"써보고 싶다"** 의사 표현
- [ ] 멀티테넌시 **2주 내 구현 가능** 확인

**No-go 시그널:**
- 내부 팀원도 안 쓴다 (주간 활성 3명 이하)
- 수동 무결과율 미개선 (알고리즘 한계)
- 스킬 생성 멈춤 (콘텐츠 생태계 미작동)

**Go 시 검증 순서:**

```
내부 개선 완료 (Phase 1-2, ~3/21)
  ↓
Go/No-go 판단 (~3/31)
  ↓
외부 알파 테스트 — 친분 있는 2~3개 팀 (4월)
  ↓
결과 기반 MVP 범위 확정 + 과금 모델 결정
  ↓
퍼블릭 베타 (5~6월)
```

**외부 서비스화 시 필요 사항:**

| 항목 | 현재 | 필요 | 난이도 |
|------|------|------|--------|
| 멀티테넌시 | 단일 팀 (@gpters.org) | 팀별 격리 워크스페이스 | 높음 |
| 셀프서비스 온보딩 | 수동 설정 | 한 줄 설치 | 중간 |
| 팀 관리 | 없음 | 멤버 초대, 역할 | 중간 |
| 공개/비공개 스킬 | 모두 내부 | 팀 전용 + 커뮤니티 | 낮음 |
| 과금 | 없음 | 무료/프로 구분 | 낮음 |

**수익 모델 (하이브리드 추천):**

| 플랜 | 가격 | 포함 |
|------|------|------|

| 개선 제안 시스템 | ✅ `suggest_improvement` / `resolve_suggestion` |
| 검색 품질 | ⚠️ 측정 왜곡으로 실제 상태 파악 불가 |

**경쟁 우위:**
- MCP 기반 멀티클라이언트 — 도구 종속 없음

- 사용 행태 분석 — 스킬 ROI 측정 가능
- 개선 제안 시스템 — 협업 기반 스킬 진화
