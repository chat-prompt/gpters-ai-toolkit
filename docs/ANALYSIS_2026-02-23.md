## 요약

Phase 1-2 구현은 완료되었고, 에이전트 자동 추천은 정상 작동 중이다. 7일간 77건의 시맨틱 검색이 발생했으며, 전부 에이전트(Claude Code/OpenCode)가 사용자 프롬프트를 보고 자동으로 실행한 것이다.

**핵심 문제는 매칭 정확도다.** 추천은 잘 일어나지만, 맞는 스킬을 못 찾아준다:
- 14.3%는 아예 결과 없음 (무결과 11건)
- ~9%는 불필요한 검색 (noise)
- 일반 사용 기준, 검색 후 조회까지 이어진 비율은 **20%** → **80%는 miss**

인프라 상태:
1. **세션 추적 시스템 배포 직후** — 구현 완료, 데이터 축적 대기. 클라이언트 리포트 훅은 0건 수신 (검증 필요)
2. **시맨틱 검색 응답시간 2.6초** — 목표 500ms의 5배

## 3. 기술 분석: 검색 파이프라인

### 3.1 임베딩

- **모델:** Gemini `gemini-embedding-001` (3072차원, halfvec)
- **임베딩 대상:** `name + description + tags + readme(1000자) + content(2000자)`
- **한계:**
  - content 2000자, readme 1000자에서 잘림 → 긴 스킬의 뒷부분 미반영
  - 필드 간 가중치 없음 (name과 content가 동등 비중)
  - 배치 API 미지원 → N개 항목 = N번 API 호출

### 3.2 벡터 검색

- **유사도:** Cosine Distance (PostgreSQL `<->` 연산자)
- **기본 threshold:** 0.3 (매우 낮음), skill-suggest에서 에이전트가 0.65로 필터링
- **정렬:** 유사도 단일 신호 (인기도/신선도 미반영)
- **응답시간:** 평균 2,637ms (임베딩 API 호출이 병목)

### 3.3 skill-suggest 구현 (플러그인별)

| | Claude Code | OpenCode | Codex |
|---|---|---|---|
| **방식** | Shell 스크립트로 힌트 주입 | TypeScript로 직접 MCP 호출 | Skill 파일로 수동 참고 |
| **자동 트리거** | ✅ 매 프롬프트마다 힌트 | ✅ chat.message 훅 | ❌ 없음 |
| **검색 주체** | Claude가 판단해서 호출 | 훅 코드가 직접 호출 | 사용자 |
| **스킵 로직** | Claude에 위임 | 정규식 패턴 | 없음 |

> 세 플러그인의 구현이 완전히 다르다. 77건 전부가 에이전트 자동 추천.

### 3.4 검색 방식 3가지

| 방식 | 대상 필드 | 용도 |
|------|-----------|------|
| Vector (semantic_search) | name, description, tags, readme, content | 의미 기반 |
| FTS (searchCatalogItems) | name, description, readme, tags | 키워드 기반 |
| Keyword (search_plugins) | name, description, readme, tags | ILIKE 매칭 |

> content 필드는 **Vector에서만 반영**, FTS/Keyword에서는 제외됨.

### 4.4 사용자 맥락 수집: 검색 시점에서 해결

현재 검색 쿼리는 **에이전트가 가공한 키워드**만 기록된다:
- 기록: `"slack message search mention"`
- 누락: 사용자 의도 + 이전 대화 맥락

**세션 종료 시 수집은 비현실적이다.** client_context 수신 0건이 증명하듯, 세션 종료 시점은 불안정하다 (터미널 강제 종료, 컨텍스트 소진, 네트워크 불안정 등).

**해결: 검색 시점에 맥락을 같이 보낸다.** 에이전트는 `semantic_search`를 호출하는 시점에 이미 전체 대화 컨텍스트를 가지고 있다. `userContext` 필드를 추가하면 된다:

```
semantic_search(
  query: "slack message search",
  userContext: "슬랙 멘션 자동 수집 봇 구현 중.
               airtable 연동 완료, 슬랙 API 연결 단계. cron 주기 실행 예정."
)
```

**구현 범위:**
1. `semantic_search` 도구 스키마에 `userContext` 옵션 필드 추가
2. skill-suggest 힌트에 "대화 맥락 요약을 userContext에 포함하세요" 지시 추가
3. actionLog 기록 시 userContext 필드 저장

**트리거 신뢰성:** 검색이 일어나는 시점에 수집하므로 100%. 세션 종료를 기다리지 않는다.

**활용:**

| 용도 | 설명 |
|------|------|
| 매칭 실패 진단 | 사용자 의도 vs 에이전트 검색어 vs 반환 결과 3자 대조 |
| 검색 품질 개선 | userContext를 임베딩에 활용 → query만 쓸 때보다 정확한 매칭 가능성 |
| 스킬 공급 판단 | 어떤 작업 맥락에서 스킬이 부족한지 분석 |

> **참고:** `write-post` 스킬(DEVLOG 생성)에 클라이언트 세션 파일 파싱 방법론이 존재한다 (Claude Code JSONL, OpenCode storage, Codex sessions). 세션 종료 리포트를 보강할 경우 참고할 수 있으나, 검색 시점 수집이 우선.

## 6. 기획 관점 진단

### 6.1 두 핵심 문제

**문제 1 — 매칭 정확도 (추천이 맞는 스킬을 못 찾는다)**

추천은 작동 중이다 (77건/7일). 그러나 80%가 miss. 원인:

| 레이어 | 문제 | 비중 |
|--------|------|------|
| A. 스킬 메타데이터 품질 | description 부실, 임베딩 길이 제한 | 낮음 (대부분 해결, 1개 남음) |
| B. 검색 파이프라인 | 쿼리 전처리 부재, 단일 신호 정렬, 2.6초 응답 | **높음** |
| C. 스킬 공급 부족 | 필요한 스킬이 없음 (SMS, Remotion 등) | **높음** |

**문제 2 — 효용성 (스킬을 찾아도 도움이 되는가)**

현재 측정 불가. 배포 이후 "실제 사용 → 효용 체감" 구간이 추적되지 않는다. 세션 추적 시스템은 구현 완료됐으나 배포 직후(2/23)라 데이터 축적 전이며, 클라이언트 리포트 훅은 아직 실제 전송이 확인되지 않았다.

또한 두 가지 팀 피드백이 효용성 문제의 본질을 시사한다:

**피드백 A — 대화 로그 수집에 대한 거부감:** 팀원들이 본인의 대화 내용이 분석되는 것에 불편함을 느낀다. 수집 범위를 최소화해야 한다: 대화 내용 대신 스킬 사용 횟수, 검색 성공/실패 여부, 작업 카테고리 수준만 수집하는 방안 검토 필요.

**피드백 B — "외부 스킬을 가져다 써도 생산성 향상을 못 느낀다":** DB 분석 결과 스킬 사용에 명확한 두 층위가 존재한다:

| 층위 | 대표 스킬 | 30일 조회 | 특징 |
|------|----------|----------|------|
| **즉시 효용** (업무 자동화) | gpters-product-coupon, airtable-integration, refund-processor | 30회, 14회, 4회 | 특정 업무를 끝까지 자동화 |
| **누적 효용** (방법론 변화) | dispatching-parallel-agents, subagent-driven-development, test-driven-development | **전부 0회** | 일하는 방식 자체를 변경 |

73개 스킬 중 "방식 변화" 스킬(병렬 에이전트, TDD, 체계적 디버깅 등)이 10개 이상 존재하지만, **30일간 조회가 단 한 건도 없다.** 반면 "즉시 효용" 스킬(쿠폰 관리, 환불 처리 등)은 활발히 사용됨. 이는 문제가 스킬 공급이 아니라 **발견/동기부여**에 있음을 시사한다. 사용 일지에서 두 층위의 체감 차이를 검증해야 한다.

### 6.2 린캔버스와의 관계

린캔버스의 가치 제안: "맥락에 가장 맞는 스킬을 찾아서 자동으로 사용하게 해준다"

| 가치 제안 요소 | 현재 상태 |
|-------------|-----------|
| 자동으로 찾아주는 기능 | ✅ 작동 중 (에이전트가 자동 검색) |
| **맥락에 맞는 스킬** | ❌ 매칭 정확도 20% (80% miss) |
| **사용하게 해주는 경험** | ❌ 마크다운 텍스트 덤프, 사용자가 알아서 적용 |
| **타겟 (사업가/크리에이터)** | ❌ 현재 유저 전원 개발자, 스킬 전부 코딩 스킬 |

> "찾아주는" 건 되지만 "맥락에 맞게"와 "사용하게"가 안 되는 상태.
