# Slack 에이전트 업무방 대화 규칙

이 문서는 이 저장소의 작업을 Slack 에이전트 업무방에서 요청·조율할 때 적용하는 공통 규칙이다.
채널 목록을 짧고 읽기 쉽게 유지하면서, 작업 맥락과 검증 기록은 잃지 않는 것이 목적이다.

## 기본 형식

에이전트 업무방의 **채널 원문**에는 아래 두 가지만 한 줄로 쓴다.

1. 작업할 에이전트 멘션
2. 대괄호 주제와 짧은 제목

```text
@에이전트 [주제] 한 줄 제목
```

채널 원문에 긴 배경, 단계별 명령, 로그, 체크리스트, 진행 상황, 최종 결과를 붙이지 않는다.

모든 상세 내용은 원문의 **스레드**에서 이어간다.

- 배경과 현재 상태
- 실행 요청과 보호 조건
- 진단·검증 절차
- 질문과 답변
- 중간 진행 상황과 최종 결과
- 관련 담당자 호출

민감정보, 토큰, 인증정보, 원문 transcript, 프롬프트·응답은 채널과 스레드 어디에도 평문으로 올리지 않는다.

## 뽀둥이 업무방

- 채널: `#023-뽀둥이-업무방`
- 뽀둥이 멘션: `<@U0AP03YMX18>`

권장 원문 형식:

```text
<@U0AP03YMX18> [텔레메트리] Claude Code 자동 수집 복구·2회 검증
```

작업이 시작된 뒤에는 새 채널 원문을 만들지 말고 기존 스레드에서 후속 대화를 계속한다.

이미 긴 원문을 올렸다면 상세 내용을 먼저 스레드 댓글로 옮긴 뒤, 원문을 멘션과 한 줄 제목으로
수정한다. 상세 내용을 보존하기 전에 원문부터 줄이지 않는다.

## 뽀짝이 방

뽀짝이는 방이 두 개고 **쓰임이 다르다.** 섞어 쓰지 않는다.

| 방 | 쓰임 | 원문 형식 |
|---|---|---|
| `#021-뽀짝이-업무방` | 팀원·타타님에게 묻거나 업무를 요청할 때 | 위 기본 형식(멘션 + 한 줄 제목, 상세는 스레드) |
| `#024-뽀짝이-디버깅` | 하영·진우가 뽀짝이 자체를 고칠 때 | **원문에 상세를 다 쓴다** (아래) |

- 뽀짝이 멘션: `<@U0AGV1N6YDP>` · `#024` 채널: `C0BUF7RC2SD`

### `#024-뽀짝이-디버깅` 이 기본 형식과 다른 이유

이 방은 사람 둘이서 에이전트를 진단하는 방이고, 한 요청이 곧 한 실험이다. 요청·보호 조건·
보고 형식을 스레드로 내리면 에이전트가 원문만 보고 답을 시작해 실험이 어긋난다. 그래서
**요청 전체를 원문 한 건에 담는다.** 후속 문답만 그 원문의 스레드에서 이어간다.

원문에 넣는 것:

1. `<@U0AGV1N6YDP> [주제] 한 줄 요약` + **보호 조건을 제목 줄에 붙인다**
   (예: `(읽기만, 파일 수정 없음)` / `(읽기만, 설치·로그인 없음)`)
2. 배경 한 문단 — 왜 지금 이걸 묻는지
3. 확인·실행할 것을 번호로. **답 길이를 지정한다** (예: "각 1줄", "각 3줄 이내")
4. 컨텍스트만으로 답할지 도구를 써도 되는지 명시. 모르면 `[컨텍스트에 없음]`이라고 답하게 한다
5. 이번 턴에 **하지 말 것**을 마지막 줄에 못 박는다 (예: "이번 턴엔 설치하지 마")

### 두 방 공통 주의

- **형제 봇 이름을 본문에 쓰지 않는다.** `mentionPatterns`에 걸려 그 봇이 소환된다.
  역할어로 쓴다 (예: "다른 팀 에이전트", "공유 스킬 담당").
- 계정·권한·사람 신원이 얽힌 질문은 채널이 아니라 **DM**으로 한다.
- 토큰·기기 코드·자격증명은 원문·스레드·DM 어디에도 올리지 않는다.

## 처음 사용하는 방

새로운 에이전트 방이거나 기존 대화 규칙을 확인할 수 없는 방에서는 규칙을 임의로 추측하지 않는다.
첫 상세 작업 요청을 보내기 전에 최하영님(`<@U0BP4R0CUSD>`)을 호출해 그 방의 대화 규칙을 확인한다.

```text
<@U0BP4R0CUSD> [채널 규칙 확인] 이 업무방의 원문·스레드 사용 규칙을 알려주세요
```

규칙이 확인되기 전에는 긴 작업 지시를 채널 원문에 게시하지 않는다. 새 규칙이 확정되면 이 문서에
해당 방의 멘션·제목 형식·스레드 규칙을 추가해 다음 작업자가 그대로 따를 수 있게 한다.
