# Slack 에이전트 업무방 대화 규칙

이 문서는 Geniefy 에이전트(Claude Code·Codex)가 Slack 에이전트 업무방에서 봇에게 작업을 요청·조율할 때 적용하는 공통 규칙이다. 어느 레포에서 일하든 이 문서가 정본이다.
채널 목록을 짧고 읽기 쉽게 유지하면서, 작업 맥락과 검증 기록은 잃지 않는 것이 목적이다.

## 스레드 선택: 새 작업은 새 스레드가 기본

2026-09-09 사용자 정정: **새 작업 요청은 새 원문과 새 스레드로 시작한다.**
같은 에이전트·같은 저장소·같은 수집기 주제라는 이유만으로 예전 스레드를 재사용하지 않는다.
이전에 끝난 검증 뒤의 새 버전 업그레이드나 별도 실험도 새 작업이다.

- **기본:** 새 원문(대상 멘션 + 짧은 제목)을 올리고, 그 원문의 스레드에 상세 요청을 쓴다.
- **예외:** 기존 문맥이 꼭 필요한 진행 중 작업의 직접 후속(방금 받은 질문의 답, 승인, 같은 실행의 결과 확인)만 기존 스레드에 잇는다.
- 이전 기록이 참고로 필요할 뿐이면 새 요청에 짧은 요약과 원문 링크를 넣는다. 이력 전체를 읽게 하지 않는다.
- 채널 선택과 스레드 재사용 판단은 별개다. 올바른 방이어도 오래된 스레드가 기본 목적지는 아니다.
- 이미 보낸 요청을 옮길 때는 실행·응답 상태부터 확인해 중복 작업을 유발하지 않는다.

## 요청 목적지

| 봇 | 목적지 |
|---|---|
| 뽀둥이 | `#023-뽀둥이-업무방` (아래) |
| 뽀짝이 | 업무는 `#021-뽀짝이-업무방`, 뽀짝이 자체 수정·검증은 `#024-뽀짝이-디버깅` (아래). DM 금지 |
| 뽀케터 | 뽀케터와의 DM. DM에서도 새 작업은 새 원문과 새 스레드로 시작한다 |

위 목적지는 2026-09-09 사용자가 확인했다. 채널과 봇 ID는 Slack 조회로 확인하고, 본문에 실제 멘션 토큰을 넣는다 — 이름만 텍스트로 쓰면 호출된 것으로 간주하지 않는다.

## 기본 형식

에이전트 업무방의 **채널 원문**에는 아래 두 가지만 한 줄로 쓴다.

1. 작업할 에이전트 멘션
2. 대괄호 주제와 짧은 제목

```text
@에이전트 [주제] 한 줄 제목
```

채널 원문에 긴 배경, 단계별 명령, 로그, 체크리스트, 진행 상황, 최종 결과를 붙이지 않는다.

모든 상세 내용은 원문의 **스레드**에서 이어간다.

- 배경과 현재 상태
- 실행 요청과 보호 조건
- 진단·검증 절차
- 질문과 답변
- 중간 진행 상황과 최종 결과
- 관련 담당자 호출

민감정보, 토큰, 인증정보, 원문 transcript, 프롬프트·응답은 채널과 스레드 어디에도 평문으로 올리지 않는다.

## 뽀둥이 업무방

- 채널: `#023-뽀둥이-업무방`
- 뽀둥이 멘션: `<@U0AP03YMX18>`

권장 원문 형식:

```text
<@U0AP03YMX18> [텔레메트리] Claude Code 자동 수집 복구·2회 검증
```

같은 작업의 후속 대화는 새 채널 원문을 만들지 말고 기존 스레드에서 이어간다. 새 작업은 위 기본값대로 새 스레드로 시작한다.

이미 긴 원문을 올렸다면 상세 내용을 먼저 스레드 댓글로 옮긴 뒤, 원문을 멘션과 한 줄 제목으로
수정한다. 상세 내용을 보존하기 전에 원문부터 줄이지 않는다.

## 뽀짝이 방

뽀짝이는 방이 두 개고 **쓰임이 다르다.** 섞어 쓰지 않는다.

| 방 | 쓰임 | 원문 형식 |
|---|---|---|
| `#021-뽀짝이-업무방` | 실제 업무 조율 — 팀원·타타님에게 묻거나 결정을 받아야 할 때, 뽀짝이에게 팀원 호출을 부탁할 때 | 위 기본 형식(멘션 + 한 줄 제목, 상세는 스레드) |
| `#024-뽀짝이-디버깅` | 하영·진우가 뽀짝이 자체를 고칠 때 | **원문에 상세를 다 쓴다** (아래) |

- 뽀짝이 멘션: `<@U0AGV1N6YDP>` · `#024` 채널: `C0BUF7RC2SD`
- `#뽀피터스알림`·`#022 경보`는 자동 보고·경보용이다. 요청 방으로 쓰지 않는다.

⚠️ **뽀짝이는 DM을 받지 않는다.** DM으로 보내면 답이 오지 않고 조용히 묻힌다.
계정·권한처럼 채널에 적기 껄끄러운 주제라도 `#024`(하영·진우만 있는 방)에서 묻는다.
DM으로 물어야 하는 에이전트는 따로 있다 — 예: 공유 스킬 담당 에이전트는 DM 채널이
정본이고 원문 한 줄 + 스레드 상세 형식을 쓴다.

### `#024-뽀짝이-디버깅` 이 기본 형식과 다른 이유

이 방은 사람 둘이서 에이전트를 진단하는 방이고, 한 요청이 곧 한 실험이다. 요청·보호 조건·
보고 형식을 스레드로 내리면 에이전트가 원문만 보고 답을 시작해 실험이 어긋난다. 그래서
**요청 전체를 원문 한 건에 담는다.** 후속 문답만 그 원문의 스레드에서 이어간다.

원문에 넣는 것:

1. `<@U0AGV1N6YDP> [주제] 한 줄 요약` + **보호 조건을 제목 줄에 붙인다**
   (예: `(읽기만, 파일 수정 없음)` / `(읽기만, 설치·로그인 없음)`)
2. 배경 한 문단 — 왜 지금 이걸 묻는지
3. 확인·실행할 것을 번호로. **답 길이를 지정한다** (예: "각 1줄", "각 3줄 이내")
4. 컨텍스트만으로 답할지 도구를 써도 되는지 명시. 모르면 `[컨텍스트에 없음]`이라고 답하게 한다
5. 이번 턴에 **하지 말 것**을 마지막 줄에 못 박는다 (예: "이번 턴엔 설치하지 마")

### 두 방 공통 주의

- **형제 봇 이름을 본문에 쓰지 않는다.** `mentionPatterns`에 걸려 그 봇이 소환된다.
  역할어로 쓴다 (예: "다른 팀 에이전트", "공유 스킬 담당").
- 계정·권한·사람 신원이 얽힌 질문은 그 에이전트가 DM을 받는 경우에만 DM으로 한다.
  받지 않으면(뽀짝이) 사람만 있는 방에서 묻는다. **에이전트마다 받는 경로가 다르므로 먼저 확인한다.**
- 토큰·기기 코드·자격증명은 원문·스레드·DM 어디에도 올리지 않는다.

## 처음 사용하는 방

새로운 에이전트 방이거나 기존 대화 규칙을 확인할 수 없는 방에서는 규칙을 임의로 추측하지 않는다.
첫 상세 작업 요청을 보내기 전에 최하영님(`<@U0BP4R0CUSD>`)을 호출해 그 방의 대화 규칙을 확인한다.

```text
<@U0BP4R0CUSD> [채널 규칙 확인] 이 업무방의 원문·스레드 사용 규칙을 알려주세요
```

규칙이 확인되기 전에는 긴 작업 지시를 채널 원문에 게시하지 않는다. 새 규칙이 확정되면 이 문서에
해당 방의 멘션·제목 형식·스레드 규칙을 추가해 다음 작업자가 그대로 따를 수 있게 한다.

## 봇에게 요청한 뒤 응답까지 추적한다

- 전송 성공은 접수·응답·작업 완료가 아니다. 요청한 채널, 원문 timestamp, 스레드 링크를 보존하고 같은 스레드를 읽어 응답을 확인한다.
- 요청을 보낸 뒤 "답이 오면 정리하겠다"고만 하고 종료하지 않는다. 현재 환경에서 제공하는 대기·감시 기능으로 추적하고, 무엇을 언제까지 확인하는지 사용자에게 알린다.
- 응답이 없으면 미응답으로 보고한다. 실제 추적 장치가 없으면 나중에 자동으로 확인할 것처럼 약속하지 않는다.
- 조사만 요청한 경우 설정 변경·발송 등 실행까지 위임하지 않는다. 다른 봇의 답변은 근거로 검토하며 사용자 승인으로 간주하지 않는다.
